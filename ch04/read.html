Build a descriptor row

Chapter four. Build a descriptor row. A useful row tells one coherent story about a capability. Part of the wording stays steady, while the evidence changes across the cells. In this workshop you will build a middle cell, compare neighbouring descriptors, and repair a row that has drifted. Then draft a row for your own assessment. Our case-study example uses illustrative grade labels. Its thresholds belong to this task; they are not a universal template.

Picture: Four cells share a blue opening, “Identifies case issues”. Mint evidence beneath it changes from accurate identification to context, relationships and justified priority.

One capability, visible differences

The guide calls this the spine-and-distinguisher structure. The spine is the common opening or sentence structure. Here, it is identifies case issues. It keeps problem identification in view. The distinguisher describes what changes in the work: locating an issue in its organisational context, explaining a symptom and cause relationship, or justifying which issue matters most. The repeated words help readers compare. But repetition alone is not enough. Every cell must still assess the same capability, and every distinction must point to evidence someone can inspect.

Picture: A blue common opening remains fixed. A mint piece slides beneath it, naming an observable distinction. Labels explain both parts without relying on colour.

Anchor both ends in the task

Begin with the capability and the intended outcome. Our illustrative case-study task treats problem identification as finding, interpreting and selecting operational issues. For this row, the minimum is accurate identification of relevant issues stated in the case. That is our local Pass anchor. If your outcome requires a causal explanation, identification alone would not be enough. At the strongest endpoint, the response places issues in context, explains symptom and cause relationships using case evidence, and justifies priorities by their impact. Define these endpoints before trying to fill every cell. Check that both are appropriate to what students were taught and asked to do.

Picture: The case-study task encloses a minimum evidence anchor and strongest endpoint. An amber note says the minimum must change when the learning outcome requires more.

Build the middle cells

Now give the intermediate cells real jobs. In this example, the Credit cell adds organisational context: where and for whom does each identified issue matter? The Distinction cell keeps that context and explains symptom and cause relationships with case evidence. For instance, a queue is an observed symptom; limited service capacity is a possible contributing cause that needs evidence. Neither step means merely writing more. Compare what a marker could point to in each response. These are designed distinctions for this row, not grades assigned automatically from a taxonomy.

Picture: The threshold and strongest endpoint remain. The two gaps fill with organisational context and evidenced symptom–cause relationships.

Read across the completed row

Read the row from left to right. Accurate identification remains in every cell. The complete descriptors also retain the evidence required in earlier cells. Context, evidenced relationships, and justified priority become visible differences. The screen abbreviates the cells so that you can compare them; the readable companion contains the full wording. Each full cell should stand on its own, without sending the reader back to another grade. Check the sequence against actual student work. If a response has strong prioritisation but unsupported causal claims, the rubric still requires professional judgement; a single impressive feature does not settle the result.

Catch a change of capability

A row can look parallel and still drift. Here the first cells identify case issues, but the last cell suddenly rewards citation formatting. The action and object have changed. Move that formatting expectation to the appropriate criterion, if it is relevant to the assessment, and restore a distinction about identifying and interpreting issues. Do not reward an unrelated feature just to make the highest cell different. Also check that the same evidence is not being rewarded again in another row. The next chapter examines that wider design question.

Picture: A citation-formatting card sits under the final cell of a problem-identification row. It moves out to an appropriate-criterion area, and a justified-priority card replaces it.

Replace praise with inspectable evidence

Adverb creep can return while you polish the wording. One cell says identifies issues well; the next says identifies issues very well. Take away well and very well. The remaining work is identical. Now name the difference: the first locates relevant issues in organisational context; the next also explains symptom and cause relationships using case evidence. A student has an action to take, and a marker has something to look for. Do not just replace one flattering word with another. Replace the hidden judgement with the evidence that supports it.

Picture: “Well” and “very well” disappear, leaving identical evidence. Context and then a supported symptom–cause explanation replace the vague pair.

A six-step drafting loop

Use a short drafting loop. Name the capability and intended outcome. Describe the strongest response and the minimum acceptable evidence for this task. Fill the middle with meaningful differences. Read across for a stable spine and consistent capability. Remove adjective or adverb-only differences. Then test the row with sample work and a colleague. This last step may send you back to revise the anchors. The order is a drafting aid, not a rule that prevents iteration. Keep the complete cells readable and make assumptions explicit.

Picture: Six steps form a loop: name capability, anchor endpoints, fill the middle, check the spine, remove praise-only differences, test with samples. An arrow returns from testing to the draft.

  1. Name the capability and intended outcome.
  2. Anchor the strongest response and local minimum.
  3. Fill the middle with meaningful evidence differences.
  4. Check parallel wording and a consistent capability.
  5. Remove adjective or adverb-only differences.
  6. Test with sample work and a colleague; revise as needed.

Two tests for every boundary

Keep three checks beside your draft. First, the capability stays steady across the row. Second, adjacent cells describe different evidence, not different levels of enthusiasm. Third, test both users of the rubric. Can a student name a concrete action to improve the work? Can a marker identify the evidence for placing a response on one side of the boundary? If either answer is unclear, rewrite or test the boundary with examples. Observable wording supports shared judgement; calibration is still needed.

Picture: Stable capability and visible evidence connect to two tests: a student can name an action, and a marker can point to evidence.

Draft your own row

Now draft one row for your own assessment. Record the capability and task, then write the minimum, strongest and intermediate cells. The labels here are working positions; replace them with your local scheme when you use the draft. Keep each cell complete enough to read independently. Check the student action and marker evidence tests before taking the row to a colleague. This activity is unscored.
